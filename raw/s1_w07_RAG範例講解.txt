影片中 1:22:02 ~ 1:49:50 是老師詳細講解實務 RAG 系統作業範例與程式碼實作的章節
。
以下為您詳細整理老師講解的完整流程，以及老師特別交代實作時必須修改、不能跟範例照抄的地方：
一、 老師如何講解作業範例（完整流程與架構）
老師將整個 RAG 實作分為兩個主要程式（Colab 檔）與一個示範資料集
：
1. 範例資料集結構（以「勞動部工讀生權益」為例）
老師展示了用 AI 協助切割好的示範資料集，將原始法規文件切分成一塊塊獨立的文字檔（.txt）
。
每塊資料皆包含結構化的格式：標題（Title）、Metadata（如連結、日期）、實際進行 Embedding 的內文（Content），以及 AI 產生的練習檢索問題與提醒標籤
。
2. 程式一：R01（打造與匯出向量資料庫）
安裝與載入套件：安裝 sentence-transformers、向量資料庫套件 FAISS 等必要工具
。
載入 Embedding 模型：範例選用 Google 的 Embedding Gemma 2 模型（適合處理中英文語意向量）
。
讀取與處理資料：上傳資料集壓縮檔，程式會自動將內文做 Embedding 轉為向向量，並將標題與 Metadata 存入資料庫
。
檢索效果驗證（關鍵步驟）：在打包前，先輸入測試問題（例如：「我在飲料店打工，公讀也有特休嗎？」），檢視向量搜尋抓出的文本與 Metadata 是否準確
。
打包匯出：將建立好的向量資料庫與對應文字打包成 .zip 檔（如 vector_DB.zip）並下載
。
3. 程式二：R02（建構 RAG 對話機器人與 Gradio 介面）
載入 LLM：使用 API 呼叫大型語言模型（範例中使用 Groq 提供的模型如 GPT-OSS / Llama）
。
載入向量庫：讀入由 R01 產生的向量資料庫壓縮檔
。
Prompt 結構設計：設定 System Prompt 與 User Prompt。當使用者提問時，系統會自動將 RAG 搜尋出來的背景資料與問題結合，讓 LLM 像做「閱讀測驗」一樣依據資料精確回答
。
測試機器人回應：測試各種提問（如：休息時間待命算工作時間嗎？），驗證機器人是否嚴格根據提供資料回答，而不是自行幻想（Hallucination）
。
部署 Gradio 網頁介面：使用 Gradio 套件啟動 GUI Web 介面，讓使用者可以透過網頁輸入問題，並設有預設的「範例問題按鈕」
。
二、 老師強調「實際要修改、不能跟範例一樣」的地方
老師在講解過程中多次提醒，這份作業有幾個關鍵地方絕對不能直接照抄範例程式碼與資料：
自訂主題與資料集（核心）：
絕對不能再用範例的「勞動部工讀生權益」資料
。
同學必須自己選擇一個感興趣的主題（例如：相機說明書、學校請假規定、選課手冊、特定領域法規等）
。第一次練習建議選擇單一且長度適中的文件（如一本 PDF 說明書）
。
資料結構設計與切割說明：
必須說明你的資料區塊（Chunk）結構是如何設計的（哪些放入內文做 Embedding，哪些做成 Metadata）
。
需在作業中說明這些資料塊是如何產生出來的（是自己手動打的，還是如何寫 Prompt 引導 AI 切割導出的）
。
向量資料庫命名與設定：
範例中的向量庫變數與打包檔名（如 vector_DB 或 vector_db.zip），應改為符合你主題的有名稱
。
自動化讀取向量資料庫（特別交代，避免助教作業無法批改！）：
程式二（R02）絕對不能讓助教手動上傳向量庫檔案
！
同學必須將 R01 產生的向量庫壓縮檔放上 GitHub 或 Google Drive，並在 R02 程式碼中寫好自動下載/讀取的指令，讓助教直接按下「全部執行」就能順利跑出對話機器人
。
System Prompt 與機器人設定：
機器人的角色定位、語氣以及「找不到資料時的回應」必須調整
。範例中寫「教材沒有足夠資訊」，實作時應改成符合你自訂機器人情境的提示語（例如「本資料庫中查無相關規定」）
。
Gradio 介面內容與範例問題按鈕：
Gradio 網頁的大標題、說明文字，以及頁面下方的範例問題按鈕（Sample Prompts），必須全部換成符合你自訂主題的問題，不能遺留範例的工讀生問題
。
