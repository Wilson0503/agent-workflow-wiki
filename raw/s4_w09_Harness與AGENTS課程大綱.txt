【簡報文件】生成式 AI 與 AI Agent 原理、專案構建與實務應用簡報執行摘要（Executive Summary）本簡報文件旨在彙整生成式 AI 從傳統「對話型大語言模型（Chat-based LLM）」跨越至現代「代理型 AI（AI Agent）」的核心原理、工具選擇、專案架構及實作應用。現代 AI 應用的關鍵範式轉移在於角色定位的轉變：使用者從過去需要手動整理資料、複製貼上的「打工仔」，轉變為只需下達明確目標與驗收標準的「管理者/老闆（出一張嘴）」。AI 則透過獲取本機或雲端資料夾存取權限、調用工具（Tool Use）與執行多步驟計畫，成為能夠自動完成複雜專案的實體員工。核心重點摘要：AI Agent 核心定義：AI Agent = 大語言模型（LLM 大腦） + 控制工程（Harness Engineering）。其中 Harness Engineering 涵蓋 Prompt、RAG、機制的設計，是決定 Agent 效能高低的關鍵。專案型設定檔（員工手冊）：透過在專案資料夾中建立 agent.md 或 claude.md（或 gemini.md），以清晰的規格書格式傳達專案目標、輸出格式、約束條件與驗收標準，取代散亂的對話提示詞。卡帕西（Karpathy）LMWiki 實作範式：展示如何利用 AI 將原始文本切碎並結構化為互相連結的 Markdown 知識庫（LMWiki），擺脫傳統向量 RAG 的不可解釋性，並能自動轉化為 HTML 簡報與網頁。主流代理工具生態：包含付費平台（ChatGPT Work/Codex、Claude Cowork/Code、Gemini/Antigravity）與本地/開源方案（OpenWorker + Ollama），企業可依據斷線安全需求或算力進行取捨。前沿研究與基礎觀念：解析 Google DeepMind 的 SIMA 3D 遊戲 Agent 研究（證明語言引導與預訓練模型提升泛化能力）；同時澄清「機器學習訓練」的本質——神經網路訓練是在更新權重（$W$）與偏置（$B$）的參數，而非單純給予 GPT 風格提示詞。一、 AI Agent 的核心概念與範式轉移1.1 從對話型 AI 到代理型 AI傳統對話型 AI（如早期 ChatGPT、Claude）本質上僅進行文字接龍，無法直接觸及電腦檔案系統或自動操作外部工具。現代代理型 AI（AI Agent）則突破了此限制。比較項目傳統對話型 AI (Chat-based LLM)現代專案型 AI Agent互動模式單次一問一答，全程需人工在場多步驟自主執行，使用者交代任務後可離場能力範圍僅能在對話框內生成與接收文字/圖片可讀寫本機檔案、建目錄、開瀏覽器、調用工具輸出成果單段回答或草稿完整專案成果（如整套網頁、知識庫、檔案分類系統）使用者角色執行苦工的「打工仔」（需手動存檔、搬移）定義規格與計畫驗收的「管理者/老闆」AI 角色僅出嘴說明的顧問具備執行力的員工/同事1.2 Harness Engineering 的本質與架構在現代 AI 領域，「Harness Engineering（控制/配備工程）」是打造高可用 AI Agent 的核心。公式定義：$\text{AI Agent} = \text{AI Model (LLM 大腦)} + \text{Harness}$基底模型現狀：當前世界頂級的大型語言模型（如 GPT、Claude、Gemini）基礎實力差距已逐漸縮小。決定實際應用優劣的關鍵，在於如何設計 Harness（引導 AI 做事的方法、檢查機制與工具介面）。範疇劃分：RAG Engineering 與 Graphite Engineering 等均屬於 Harness Engineering 的分支。二、 專案型 AI Agent 的構建邏輯與機制2.1 專案資料夾與權限授權建立專案型 AI Agent 時，不需要為其編寫複雜的底層程式。核心步驟包括：在電腦本機（或雲端）建立一個專用專案資料夾。賦予 AI 代理工具該資料夾的完整讀寫與存取權限。將所有輸入原始檔（如 paper、ideas、圖片）與產出的結果（如 wiki、notes、html）集中在此資料夾管理。2.2 員工手冊：agent.md / claude.md為了讓 AI 員工精準執行任務，必須編寫「員工手冊/設定檔」（如同系統提示詞 System Prompt 的專案專用版）：常見檔名：agent.md（通用慣例）、claude.md（Claude 體系習慣）、gemini.md 等。大語言模型載入資料夾時會自動讀取該設定檔。高質量指令（給好老闆的交辦原則）：成果定義：明確交代最終產出為何（格式、儲存路徑、網頁架構）。約束條件：設定嚴格邊界（如：絕對不可刪除任何原始檔案；無法分類者放進 待確認 資料夾）。驗收標準：提供評判標準與步驟。先計畫後執行：要求 AI 在動手修改/搬移檔案前，先提出「分類/執行計畫」供人類管理員審查授權。2.3 技能打包（Skills）當與 AI 討訪並實驗出良好的工作流程（如特定的日系手帳簡報風格 HTML 生成邏輯）後，可要求 AI 將此 SOP 打包成「Skill」。Skill 可在同一個專案或跨專案反覆調用，確保 AI 產出的品質與風格不會隨機波動。三、 開發工具與部署平台比較目前支援專案型 AI Agent 操作的主要工具與平台特性如下：工具 / 平台授權/費用類型主要適用場景與特性ChatGPT (Work / gemini.md。OpenWorker + Ollama完全開源 / 本地端可配合本地小模型（如 Llama 體系）運行。適用於要求 100% 斷線安全與資料隱私的企業情境。註：小模型表現仍與頂級雲端模型有差距。GBolt (Bolt.new)雲端託管全雲端硬碟架構專案，不在本機建立專案目錄，需使用其雲端空間。M (Meta Agent)未在台開放走類似 Agent.md 模式，整合生態圈機制。四、 實務案例與應用實作分析案例一：自動化桌面檔案分類器傳統做法：AI 僅能提供建議文字，使用者需手動建資料夾、按檔名拖拉 87 個檔案。Agent 做法：使用者輸入：「請整理這個資料夾，先提計畫給我看。」Agent 自行讀取目錄檔案與副檔名，擬定 5 大類分類計畫（作業、照片、講義、安裝檔、待確認）。管理員確認計畫後，Agent 自行調用系統工具建立資料夾並完成檔案搬移，最後回報結果。案例二：Karpathy 式 LMWiki 個人知識庫與動態簡報生成本實作參照 Andrej Karpathy 的思維，旨在打造高可解釋性的個人 Wikipedia：[原始文獻 / Papers] 
       │
       ▼ (AI 自動閱讀與切塊)
[LMWiki 知識庫] ── 包含 index.md (全庫索引) + 相互連結的 *.md 條目
       │
       ▼ (完全基於內部知識庫進行研究與提煉)

優勢：取代了傳統向量資料庫（Vector RAG）檢索的「黑盒子」缺點。人類使用者與 LLM 均可直接讀取 index.md 與結構化條目，找對找錯一目瞭然。簡報自動化：要求 AI 依據知識庫生成 Note，再套用低飽和度日系粉彩色調（日系手帳風格），產出包含內建 LaTeX 數學公式與小圖貼（Assets）的 HTML 網頁簡報，並自動將新頁面掛載至首頁 index.html。案例三：全自動粉專貼文與圖輯工作室 (代一部 AI)流程架構：定時排程：每日早晨 7:30 自主聯網搜尋最新熱門 AI 趨勢與新聞。主題研究與草稿：挑選重點議題，寫入 ideas 資料夾並生成貼文初稿。審核與視覺生成：管理員對內容進行微調後，Agent 自動提煉標題，調用專門的繪圖 Agent/Prompt 生產對應風格的封面圖與系列貼圖。自動發布準備：完成最終圖文排版與發布準備。五、 學術研究與基礎神經網路複習5.1 前沿 Agent 研究：Google DeepMind SIMAtranscript 中由學生分享了 Google DeepMind 於 2024 年發表的重磅研究 SIMA（A Generalist Agent in 3D Multi-World Environments）：目標：打造能在多款 3D 開放世界遊戲中，僅看螢幕畫面、聽懂自然語言指令，並透過鍵盤滑鼠操作的泛化 Agent。模型架構：Spark：預訓練圖文模型，負責將影像細節對應至文字。Finucky (Fennnec)：預訓練影片預測模型，理解畫面接下來的動態變化。Multimodal Transformer + Transformer-XL：整合多模態資訊並結合記憶狀態。關鍵實驗結論：零樣本泛化能力（Zero-shot Generalization）：未在特定遊戲中訓練的 SIMA，表現可達專家級 Agent 的 90%。預訓練模型重要性：若將預訓練的 Spark/Finucky 替換為從頭訓練的 ResNet，效能明顯下滑（從 165% 降至 120%）。語言的核心作用：移除自然語言指令輸入（Remove Language / Class-Free Guidance）會導致 Agent 成功率大幅下跌，證明語言訓練能顯著加速學習並提升跨環境泛化力。5.2 基礎神經網路與「訓練」的本質針對課程作業（作業二手寫辨識與作業三神經網路設計）進行觀念釐清：1. 什麼是函數（Function）？函數本質上是定義域（Domain/問題）到子域（Codomain/答案本）的對應關係 $y = f(x)$。傳統數學函數：$x=3 \to y=6$（乘 2 的關係）；$x=5 \to y=25$（平方關係）。現實生活中的函數 mapping：生日與年份 $\to$ 十二生肖 / 星座（對應至 12 種固定分類）。星盤：輸入（年月日、時間、經緯度）$\to$ 輸出（太陽星座、上升星座等固定格式）。YouBike 站點空位預測：輸入（星期幾、時間點、天氣/降雨機率、歷史車輛數）$\to$ 輸出（半小時後的空車率等級分類）。高爾夫球揮桿分析：輸入（揮桿單張影像）$\to$ 輸出（判定處於 8 個 Checkpoint 的哪一個階段）。2. 「訓練機器人」的真實意義許多初學者誤以為「把一段文字貼給 ChatGPT 叫它改寫風格」就叫做訓練。這並非機器學習意義上的訓練。真實的神經網路訓練流程如下：輸入轉換：以 $28 \times 28$ 的手寫數字影像為例，輸入為一串長度 784 的像素亮度數值向項。前向傳播：影像資訊通過神經網路，計算 $Y = W \cdot X + B$（權重 $W$ 乘上輸入 $X$ 加偏置 $B$）。參數更新（Training）：初始時，權重 $W$ 與偏置 $B$ 均為隨機設定，產出的預測極不準確。透過計算損失函數（Loss Function），比對預測結果與真實標籤。利用反向傳播算法（Backpropagation），反複修正並更新內部的 $W$ 與 $B$ 參數（例如將華氏/攝氏轉換參數逐步調至 1.8 與 32）。直至模型面對沒看過的測試資料，也能正確輸出預期結果。這才稱為完成神經網路的「訓練」。

1. 簡報成果展示與特色
以 HTML 網頁作為簡報格式： 講師示範讓 AI 根據前面建構的個人知識庫筆記，自動生成一份份的 HTML 簡報網頁
。使用 HTML 的好處是相容性高、可跨平台瀏覽，且具備互動切換功能（如製作「上一頁／下一頁」按鈕），甚至能完整排版漂亮的數學符號（LaTeX）與圖表
。
風格定制與視覺素材（Assets）：
講師在 Prompt 中引導 AI 採用「低飽和度粉彩色調」與「日系手帳雜誌風」
。
網頁中穿插的插圖與圖貼，是預先放置在 assets/ 資料夾中的自訂素材，規範 AI 固定取用該資料夾中的圖片進行排版裝飾
。
將滿意成果打包成 Skill（SOP）： 當與 AI 來回討論、試做並獲得滿意的版面風格後，講師指示 AI 將生成投影片的方法打包成一個 Skill
。這樣未來每次要求它製作簡報時，都會固定遵循這套規範，不會每次產出風格迥異
。
2. 首頁導覽與自動更新機制（index.html）
根目錄必備 index.html：專案根目錄必須有一份總首頁，集中展示並連結到每一篇生成的簡報或文章頁面
。
全自動維護更新：使用者不需手動修改程式碼，而是要在員工手冊（規則檔）中要求 AI：每當生成一份新的簡報或文章時，必須自動在 index.html 首頁上新增對應的卡片連結，讓專案能像知識入口網站一樣不斷自動擴充
。
3. 專案繳交重點與 GitHub 規定
主題自由發揮： 同學可自選任何感興趣的主題（例如：喜愛的電視劇、韓團介紹、台北咖啡店／美食地圖、AI 入門問答或課程講義等），只要能讓 AI 自動整理資料並持續產出內容即可
。
必須上傳「完整專案架構」至 GitHub：
切勿只上傳最後產出的 index.html 或網頁成品
。
必須將整個專案資料夾完整 push 到 GitHub，包含：
員工手冊／規則設定檔（如 agent.md、gemini.md 或 claude.md）
。
素材資料夾（如 assets/）
。
中間過程與產出檔案（如知識庫、筆記、各子頁面 HTML）
。
