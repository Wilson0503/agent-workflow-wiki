🛠️ 五、 07C 實作示範（Planning 規劃型 Agent）與關鍵細節
1. 範例定位與路線選擇
網址與版本：範例路徑為 [suspicious link removed]
。其中 07A 為 Reflection（反思型）、07B 為 Tool Use（工具使用型：飲料店範例）、07C 則為 Planning（規劃型）
。
老師特別推薦 07C：若對程式較不熟悉，老師強烈建議選擇 07C 來實作
。07C 的主題是「原因式思考生成器」（將倒楣事正向轉化），但同學可以將其替換為任何需要「打草稿」的情境（如文章寫作、旅遊規劃等）
。作業只需從這三種模式中選擇一種實作即可
。
2. 多階段呼叫與燒 Token 的現實陷阱（API 額度與穩定度）
Agent 為何極度燒 Token：傳統問答只需呼叫一次模型，但 Agent 屬於多階段（Multi-stage）架構（例如第一階段負責規劃/打草稿，第二階段才正式生成內容）
。每一階段都在重複呼叫模型，導致 Token 消耗速度呈倍數成長
。
Groq 免費 API 的限制：在測試中發現 Groq 免費 API 非常容易在執行到一半時因達到用量限制而中斷
。若要改用較小的模型（例如避免使用過大的 120B 模型）可以降低斷線機率
。
商業應用的實務建議：如果未來要打造穩定的商業級應用，免費 API 絕對無法滿足需求，必須採用付費 API（按用量計費）
。
3. 程式碼防呆與測試機制（True / False 開關）
保護 API 額度的設計：範例程式碼中寫滿了測試開關（預設為 False）
。這是為了防止學生在執行 Colab Cell 時無意間發送大量 API 請求而快速燒光額度
。
啟動 Gradio 的操作：若要測試中間特定環節，需手動改為 True 才能跑出測試結果；而在啟動 Gradio 互動介面時，程式預設已幫大家設為 True 以便直接執行
。
4. AI 幫忙寫 Prompt 的隱藏陷阱（Prompt 長度極限）
不要盲目相信 AI 生成的長 Prompt：當我們請 ChatGPT 幫忙寫 Prompt 時，AI 往往會寫得極度詳細且冗長
。
模型吃不下過長指令：老師特別口頭提醒，某些生成模型其實吃不下過度複雜或過長的 Prompt，強行傳入反而會導致模型效果變差甚至壞掉，必須親自測試並精簡
。
5. 思考過程（CoT / DeepSeek 模式）的本質
為什麼把思考過程印出來？：一般商業 AI 會隱藏思考過程，但 07C 範例在 Gradio 介面上特意將「思考過程（Reasoning Draft）」同步顯示出來
。
思考的本質就是「打草稿」：老師強調，所謂的 AI 思考能力並沒有神秘的靈魂或真正在「想事情」，其本質就是「打草稿」
。這個打草稿的邏輯完全是由人類透過 System Prompt 預先教導它的（例如：先確認事實、評估失落點、發想幽默切入點，最後才生成正文）
。
