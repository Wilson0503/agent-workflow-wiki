Agent = Model + Harness

Harness
Model
理解與生成語言的大腦
  • 包含做事方法、檢查機制、工具介面

三種基本做事方法

Reflection

先產生結果，再自己檢查、修改

Tool Use

依需求選工具，例如計算機、搜尋

Planning

先拆解步驟，再照計畫一步步做

AI 的「思考」其實是打草稿

  • AI 的思考沒有神秘靈魂，本質就是打草稿
  • 步驟是人用 System Prompt（事先給的規則）教的
  • 教步驟的 Prompt 也別寫太長，模型可能吃不下
  1. 1確認事實
  2. 2評估失落點
  3. 3發想幽默切入點
  4. 4生成正文
講者備註：07C 是「把倒楣事正向轉化」的思考生成器。
planningprompt-engineering06

串起來 ①：Reflection Loop

  • ① 作者 Agent 產生初版
  • ② 審查員 Agent 依標準列出缺點與建議
  • ③ 作者修訂後再送審，反覆來回
  • 關鍵：要有客觀的放行條件
  • 第八週是自己反思；這裡把作者和審查員分開
reflection-loopreflection07

迴圈一定要有煞車

  • 最大次數例如最多修訂 3～5 次就強制停
  • 資訊不足即停缺原始資料就請人類補
  • 成本控管避免無效重複修訂浪費 Token

為什麼會燒錢？

  • Agent 每多一階段就多呼叫一次模型
  • 例如 Groq 免費 API，容易跑到一半因額度中斷
講者備註：Token 可以想成模型的用量；每呼叫一次模型就消耗一次，Agent 階段越多，用量和費用就倍數成長。
stopping-conditionstoken-cost08

串起來 ②：Graph

  • 每個節點（Node）只專注做一件事
  • 例：A 寫大綱、B 檢查漏洞、C 輸出報告
  • 流程不是直線：可依條件跳回前面節點
  • C 發現資料遺漏 → 跳回 B，甚至退回 A
graph-workflow09

Loop 還是 Graph？先從簡單的開始

  • Loop：固定的「產生 ⇄ 審查」來回
  • Graph：依條件在不同節點間跳躍、回溯
  • 簡單 Prompt 能解決，就不要用 Loop
  • Loop 能解決，就不要堆複雜 Graph
  • 流程應從人類實際做事的步驟演化而來
Prompt先試這個
Loop一層不夠才往上
Graph需要跳回才用

人類該在哪裡出手？

  • 大綱生成後，是人類的最佳檢查點
  • 在大綱修正，可避免之後重做 HTML 的大成本
  • 管理者只抓兩關：大綱審核、最終檢查報告
  • 動手前先提計畫，讓人審核再執行

實例：這份簡報是怎麼做出來的

  • 6 份原始課程資料 → 整理成 LLM Wiki
  • 節點：Wiki → 大綱 → 逐頁內容 → HTML → 驗證
  • 生成過程中，人類只在大綱這一關審核
  • 每個 Loop 最多 3 輪，超過就停下問人

講者備註：7 處不符中有 5 處是原始資料根本沒講的事；有 4 處出在「常見誤區」段，因為模板要求至少寫 1 點，作者就自己補了常識。後來改成「沒有就寫來源未提及」，並把事實抽查提前到 Wiki 這一層。最終檢查報告就是 docs/run-log.md。

小測驗

Q1AI Agent 的公式是什麼？

AI Agent = AI Model + Harness。

Q2設計 Loop 時至少要有哪兩種設計？

客觀的放行條件，以及煞車機制（如最多 3～5 次、資訊不足即停）。

Q3用 Graph 做簡報，人類最該在哪一步檢查？

大綱生成後。在這裡修正，可以避免之後重做 HTML。

小結與參考資料

  1. Agent = Model + Harness，關鍵在怎麼安排步驟
  2. Loop 要有放行條件和煞車；需要跳回才用 Graph
  3. 人類在大綱出手，越早檢查越便宜
