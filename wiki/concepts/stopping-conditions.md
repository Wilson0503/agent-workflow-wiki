# 煞車機制（Stopping Conditions）

> 事先規定迴圈什麼時候一定要停，避免無限重做和浪費錢。

## 重點
- **最大次數限制**：例如最多反覆修訂 3～5 次就強制停止（s6）。
- **資訊不足即停**：審查發現缺乏關鍵原始資料時中斷迴圈，請人類補資料（s6）。
- **成本效益控管**：防止無效的重複修訂導致 Token 費用浪費（s6）。
- 和「客觀放行條件」搭配：一個決定何時合格，一個決定何時放棄（s6）。
- 程式層面的防呆：預設 False 的測試開關，避免誤觸大量 API 呼叫（s2）。

## 例子
- 本專案每個 Loop 最多 3 輪；wiki 和 raw 都沒有的資訊就停下來問人類（CLAUDE.md 5.2，依據 s6）。

## 常見誤區
- 只設放行條件、不設上限：品質一直達不到標準時就會無窮迴圈（s6）。
